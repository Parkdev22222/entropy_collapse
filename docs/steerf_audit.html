05수정

FSDP에서 예보 경로가 크래시 — 그리고 문서에 적힌 처방이 틀렸음

dp_actor.py _steerf_forecast · 한 번도 실행된 적 없던 유일한 경로

첫 λ>0 실행이 unembedding에 도달하며 죽었습니다. 원인은 코드 주석이 가정한 샤딩이 아니라 weight tying이었습니다. Qwen2.5는 tie_word_embeddings=True라 lm_head.weight가 embed_tokens.weight와 같은 객체이고, FSDP는 forward가 반환될 때 그 flat 파라미터를 해제합니다.

lm_head.weight is embed_tokens.weight → True
forward 이후 storage → 0 bytes
RuntimeError: setStorage: sizes [1536, 151936] … out of bounds for storage of size 0

로그에 처방 (a)로 적혀 있던 “예보를 summon_full_params로 감싸기”는 그대로는 작동하지 않습니다. 컨텍스트를 forward 주위에 두면 그 forward가 빠져나오며 파라미터를 다시 해제하기 때문입니다. verl의 FSDP 구성을 그대로 복제해 실제 1.5B에서 재현했고, 작은 모델로는 재현조차 되지 않습니다 — 아마 그래서 틀린 처방이 문서에 남았을 것입니다.

수정forward를 먼저 끝내고, 예보만 summon으로 감싸고, 캐스팅. summon은 원본 fp32 파라미터를 복원하는데 hidden은 mixed-precision bf16이라 캐스팅이 부수적이 아니라 필수입니다. 실제 학습 루프 안에서 검증 완료 — λ>0 진단이 출력되고 스텝이 완주합니다.

08수정

통계적 검정력

09미해결 · 수용

Phase 0 팔들을 pass@16으로 재평가할 수 없음

trainer.save_freq = -1

G0는 곡선만 필요하고 가중치는 불필요해서 체크포인트를 껐습니다. 결과는 나중에야 드러났습니다 — Phase 0 세 팔을 사후에 pass@16으로 채점할 수 없고, 따라서 GRPO 대비 STEER의 다양성 이득을 정량화할 수 없습니다.

판단재실행하지 않고 수용. Phase 0의 역할은 G0였고 통과했으며, 재실행에 드는 약 5 GPU-시간은 Phase 2 시드를 늘리는 데 쓰는 편이 같은 비용으로 더 강한 주장을 만듭니다.

11수정

EOS 이후 패딩이 ground truth로 채점됨

scripts/phase1_validate.py

generate는 배치 전원이 끝날 때까지 돌고 먼저 끝난 시퀀스를 패딩합니다. measured_future_entropy는 continuation이 지평선보다 짧을 때만 NaN을 넣는데, 패딩 때문에 절대 짧아지지 않습니다. offset 2에서 끝난 continuation이 …<eos><pad><pad>의 엔트로피를 실측치로 기여했고, 하류의 isfinite 필터가 그대로 통과시켰습니다.

수정각 continuation을 자기 EOS에서 절단하되 EOS 자체는 유지 — 그것을 만든 분포는 실제 정책 상태입니다. 이제 NaN 경로가 설계대로 작동합니다.

15수정

문제당 N개 샘플 생성의 평균 정확도. @N은 디코딩 방식이 아니라 샘플 개수입니다. 검증은 temperature 1.0, top-p 0.7로 샘플링합니다.

문제-내 Spearman ρ조건 1 · 통과

예보 Htogo와 Monte-Carlo 실측치의 순위상관. 문제별로 계산해 Fisher-z 평균을 내므로 문제 간 난이도 차가 지배하지 않습니다. 실측치에도 예보와 같은 γH를 적용합니다 — 할인 예보를 무할인 실측에 대고 채점하면 γ < 1이 품질과 무관한 이유로 손해를 봅니다. κ=2, γ=0.7, 25문제에서 0.841.

주의 ρ는 예보가 미래 엔트로피의 절대 수준을 맞히는지를 잽니다. STEER-F는 수준을 쓰지 않습니다 — 형제 평균을 뺀 편차인 AH를 씁니다. 높은 ρ는 필요조건이지 충분조건이 아닙니다.

아직 모르는 것

λ > 0 학습은 한 번도 실행되지 않았습니다. 지금까지의 모든 λ > 0 실행은 랜덤 초기화 헤드로 돌린 2스텝 배관 테스트입니다. 이 원장의 어떤 내용도 STEER-F가 무언가를 개선한다는 증거가 아닙니다.

RL 중 헤드는 freeze 상태입니다. MTP 보조 손실과 λ 표류 컨트롤러는 구현·단위테스트까지 됐지만 학습 루프에 연결되지 않았습니다. 즉 Phase 2는 사실상 ablation A7 조건이며, 이는 결과가 뒷받침할 수 있는 범위를 제한하므로 추론에 맡기지 말고 명시해야 합니다.

더 싼 방법이 숨어 있을 수 있습니다. RLVR은 롤아웃이 완결된 뒤 업데이트하므로, 실현된 할인 미래 엔트로피를 롤아웃에서 그냥 읽을 수 있습니다 — verl이 이미 엔트로피 텐서를 계산합니다. 헤드도, 워밍업도, 추가 forward도 필요 없습니다. 예보가 사는 유일한 근거는 실현값이 아닌 기대값을 추정한다는 것뿐이고, 이는 실험으로 답할 문제이며 Phase 2에 무료로 추가할 수 있는 arm입니다.
